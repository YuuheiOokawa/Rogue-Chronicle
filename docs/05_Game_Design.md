### 1.2 レアリティ不採用の理由（仮決定）
- ガチャ・課金を恒久的に導入しない（DEC-016）ため、レアリティによる射幸性・格差の演出が不要
- キャラ数3体（将来も少数精鋭）では、レアリティよりも**役割差別化**の方が選択の意味を生む
- レアリティがあると「低レアは使わない」という死にコンテンツが発生し、少数キャラ設計と相性が悪い
- データ上も characters テーブルに rarity 列を持たない（12_Database_Design.md と整合させる）

### 1.3 キャラ差別化方針
| 軸 | レイン | リリア | ガルド |
|---|---|---|---|
| 難易度想定 | 初心者 | 中級 | 上級 |
| 勝ち筋 | 安定継戦（高耐久+不屈） | スキル回転（SP供給） | 先手バースト（spd+クリ） |
| 弱点 | 決定力不足（伸びるのは耐久） | 被弾に弱い・事故死リスク | 長期戦・高def敵 |
| 推奨ビルド例 | 防御系レリック+回復スキル | SP軽減/回復系+高倍率スキル | クリ率・spd系+1ターン目強化 |
| 属性の意味 | 対風敵（bat）に有利 | 対火敵（fire_imp）に有利 | 対水敵（slime, dark_shaman）に有利 |

差別化は「初期値・成長係数・固有能力・属性」の4点のみで行い、**専用スキル枠や専用装備枠は作らない**（スキル/装備プールは共通。ビルドの自由度を優先。仮決定）。

## 2. ステータス定義（CORE_SPEC §5.1 / §5.4 準拠）

| コード | 名称 | 戦闘への影響（計算式） |
|---|---|---|
| hp / maxHp | HP | 0で戦闘不能（プレイヤーは敗北）。レベルアップで割合維持のまま最大値上昇（全回復なし） |
| atk | 攻撃力 | `ダメージ = max(1, floor(atk × skillMult × (100/(100+def)) × elemMod × critMod × rand(0.90〜1.10)))` の基礎値 |
| def | 防御力 | 上式の `100/(100+def)` による逓減軽減（def100で被ダメ半減。加算インフレしない） |
| spd | 素早さ | 行動順（降順）。同値はプレイヤー優先。逃走成功率 `clamp(50+(自spd−敵最速spd)×2, 20, 90)` にも使用 |
| critRate | クリティカル率(%) | `rand100 < critRate`（上限100）でクリ発動。基本5% |
| critDmg | クリティカルダメージ(%) | クリ時 `critMod = critDmg/100`（基本150%→1.5倍） |
| eva | 回避率(%) | 命中判定 `rand100 < clamp(95 + acc − eva, 50, 100)` で減算側 |
| acc | 命中率補正(%) | 同上で加算側。基本0 |
| statusRes | 状態異常耐性(%) | `状態異常成功率 = 基本成功率 × (100 − statusRes) / 100` |
| elemRes | 属性耐性(%) | 属性ごとに保持。被属性ダメージを最大−50%まで軽減（elemModに乗算） |
| sp / maxSp | SP | スキルコスト資源。初期最大10、毎ターン+2回復（リリアは+3）。「MP」表記は禁止（§4） |

- 行動力は独立ステータスとして置かず、spd＝行動順として扱う（仮決定・CORE_SPEC §5.1）
- 属性相性: 火→風、風→水、水→火が有利（1.25倍）。逆は0.75倍。無は常に等倍（§5.2）

## 3. 一時成長（ラン内のみ有効）

すべて **dungeon_runs.run_state（JSONB, DEC-011）** に保存され、ラン終了（クリア/敗北/リタイア→finalize）で消滅する。

| 要素 | 上限/枠 | 獲得手段 | 失われるタイミング |
|---|---|---|---|
| レベル | **上限20**（開始Lv1） | 戦闘勝利のEXP: `Σ 敵baseExp × (1+0.10×(floor−1)) × difficultyExpMod`。必要EXP `expToNext(L)=floor(20×L^1.5)` | ラン終了で消滅 |
| スキル | **上限8枠** | レベルアップ時の3択（common60/rare30/epic10、リロール1回/ラン+永続強化で+1）/ 一部イベント報酬。同一スキル再取得で強化Lv+1（最大3） | ラン終了で消滅。ラン中の削除はイベント/休憩で可 |
| 装備 | **3スロット**（weapon/armor/accessory 各1） | 初期装備（永続解放分から出撃時選択 SCR-205）/ 戦闘ドロップ / 宝箱 / ショップ購入 / イベント。付け替えはSCR-309（API-507） | ラン終了で消滅（永続解放装備の「解放状態」は残る） |
| バフ/デバフ | 同種は上書き（効果値大優先） | スキル・レリック・イベント・敵の行動 | **戦闘終了で消滅**（atkUp等の戦闘内バフ）。ターン数制で戦闘中にも失効 |
| パッシブ | スキル枠内 | スキル20種のうちパッシブ型（例: 常時atk+10%系）を3択で取得（該当スキルは18_Skill_Design.mdで定義） | ラン終了で消滅 |
| レリック | 同一レリック重複不可（所持数上限なし） | エリート撃破報酬 / 宝箱 / イベント（BLESS/SECRET）/ ショップ。trigger型効果（§5.8）。呪い付き2種を含む | ラン終了で消滅（呪いレリックの除去はイベントでのみ可） |
| 消耗品 | 各種**5個まで**（仮決定） | ショップ / 宝箱 / イベント / 初期所持（potion×1） | 使用時 / ラン終了で消滅 |
| ゴールド | 上限9999（仮決定） | 戦闘報酬 / 宝箱 / イベント / 装備売却（ショップ） | ラン終了で**消滅**（§5.9。将来: 永続強化「換金」で一部持ち帰り） |

### 3.1 消耗品3種（MVP・仮決定）

| code | 名称 | 効果 | 使用場面 | 入手目安 |
|---|---|---|---|---|
| `potion` | ポーション | HPをmaxHpの50%回復 | 戦闘中（行動を消費 API-402）/ マップ上でも使用可 | 初期1個・ショップ40G・宝箱 |
| `sp_potion` | マナポーション | SP+5（maxSp超過不可） | 戦闘中のみ | ショップ50G |
| `antidote` | 万能解毒薬 | 状態異常（poison/burn/paralysis/stun/weaken）を全解除 | 戦闘中のみ | ショップ30G |

### 3.2 レベルアップ仕様（CORE_SPEC §5.4 準拠）
- 成長: maxHp+8% / atk+5% / def+5% / spd+2%（×キャラ成長率係数）。端数は floor、ただし最低+1保証（仮決定）
- **全回復なし**: HP割合維持（例: HP 60/100 でmaxHpが108になったらHP 64/108）
- レベルアップごとにスキル3択（SCR-303/304、API-501/502）。スキップ選択可（報酬なし・仮決定でスキップ時SP+2の小補償 → ISSUE候補）

## 4. 永続成長（ラン終了後も残る）

### 4.1 プレイヤーランク（player_progress.rank）
- ランクEXPはリザルト（API-307）で獲得。敗北ランでも獲得（01_Game_Concept.md §3.2）
- 必要EXP: **`expToRank(R) = 100 × R^1.8`**（ランクRからR+1への必要量、floor丸め）。**上限50**

| ランクR | R→R+1必要EXP | 累計EXP（Lv1から） |
|---|---|---|
| 1 | 100 | 0 |
| 2 | 348 | 100 |
| 5 | 1,812 | 約2,600 |
| 10 | 6,310 | 約14,000 |
| 20 | 21,981 | 約77,000 |
| 30 | 45,610 | 約222,000 |
| 49 | 110,138 | 約900,000 |

- 1ランの獲得ランクEXP目安: クリア約400〜600 / 中盤敗北約150〜250（19_Balance_Design.mdで最終調整）
- **ランク報酬（仮決定）**: ランクアップごとにソウルシャード `10×到達ランク`。節目報酬:

| ランク | 節目報酬 |

| 5 | ソウルシャード+100（ボーナス） |
| 10 | 称号「探索者」+ シャード+200 |
| 20 | 称号「年代記の写し手」+ シャード+500 |
| 30 | 称号「深淵を知る者」+ シャード+1000 |

### 4.4 図鑑（player_codex, DEC-018）
- entry_type: skill / relic / enemy / equipment / character の5種を1テーブルで管理
- 登録タイミング: 初取得（skill/relic/equipment）・初遭遇（enemy）・解放（character）。**敗北ランでも登録は残る**
- カテゴリコンプリート報酬（仮決定）: 敵図鑑8/8=シャード200 / レリック10/10=300 / スキル20/20=500 / 装備全種=300
- 図鑑総登録率は実績ACH-010の条件に使用

### 4.6 ストーリー / 難易度解放
- ストーリー: STORYノード到達で断片テキスト解放（stories / player_story_progress）。MVPは忘却の遺跡の断章5話程度（仮決定・07/09で確定）。閲覧状態は永続
- 難易度解放（将来）: Hard=Normalクリア1回で解放（difficultyMod 1.3）/ Nightmare=Hardクリアで解放（1.6）。EXP・報酬も同率増加（§5.4）。MVPはNormalのみ

### 4.7 ソウルシャード（player_currencies）
- **獲得**: リザルト確定（API-307）時に `earned.soulShards × 結果係数 × (1 + 永続強化ボーナス)`。結果係数: クリア100% / リタイア80% / 敗北50%（§5.6）。他にランク報酬・実績報酬・図鑑コンプ報酬
- **消費**: キャラ解放（リリア300）/ 永続強化ツリー（総額3,780）
- 増減は currency_transactions に全件ログ（監査・不正検知用）

## 5. バランス設計方針

### 5.1 「ラン内成長が主役」の数値根拠
- ラン内: Lv1→20で maxHp ×1.08^19 ≒ **4.3倍**、atk ×1.05^19 ≒ **2.5倍**（係数1.0時）+ スキル8枠 + 装備 + レリック
- 永続: ステータス寄与は最大でも **HP+15% / ATK+9%**
- → 永続強化を全部買っても「開始が少し楽になる」に留まり、攻略の決定要因はラン内の選択に残る

### 5.2 永続強化の上限ルール
- **永続強化の総和はステータス+30%以内**（CORE_SPEC §5.9）。現行12ノードの合計はHP+15%+ATK+9%=カテゴリ別にも十分下回る
- 将来ノード追加時も「1ステータスあたり+15%以内 / 全ステ合算+30%以内」を維持（仮決定）。超える強化は「非ステータス系」（リロール回数・開始レリック・シャード効率等）で設計する

### 5.3 インフレ防止ルール
1. defは逓減式 `100/(100+def)` のため、防御の積み増しが線形無効化されない（%軽減の上限問題を構造で回避）
2. critRate上限100 / 命中clamp(50,100) / elemRes軽減上限−50% / ダメージ乱数±10%固定 — 全確率系にキャップ
3. 敵の強さは `1+0.12×(floor−1)` と種別補正（§5.4）のみで表現し、後付けの特殊補正を増やさない
4. 新スキル・新レリックは既存の数値レンジ（skillMult 0.8〜3.0）内で設計し、レンジ拡張はDEC相当の意思決定を要する
5. シャードのシンク（永続強化・キャラ解放）を先に用意し、供給過多になったら**獲得側でなく新規シンク追加**で調整する

### 5.4 ソウルシャード獲得/消費バランス試算

**ラン中の蓄積目安（earned.soulShards、仮決定・19で最終化）**: 通常戦闘+4 / 強敵+8 / エリート+15 / ボス撃破+40 / 宝箱・イベント平均+5、クリアボーナス+50。

| プレイヤー段階 | 典型的な結果 | 素点（earned） | 係数後の獲得/ラン | 1ラン時間 |
|---|---|---|---|---|
| 序盤（〜10ラン） | 階層4〜6で敗北 | 25〜40 | **約13〜20**（×50%） | 15分 |
| 中盤（10〜30ラン） | 階層8前後で敗北/リタイア | 55〜75 | **約30〜55**（×50〜80%） | 20〜25分 |
| クリア安定期 | クリア | 約100+ボーナス50 | **約150**（×100%、shard強化込み最大180） | 25〜30分 |

**解放コストとの対応（累計必要ラン数の目安）**:

| 目標 | コスト | 到達目安 |
|---|---|---|
| 最初の強化（upg_hp_1 or upg_atk_1: 100） | 100 | 5〜7ラン（実績ACH-001/002も加算され実質3〜5ラン） |
| リリア解放 | 300 | 10〜15ラン（約3〜5時間）＝ガルド解放（ACH-004=10ラン）とほぼ同期 |
| 序盤コア4ノード（hp1,atk1,gold1,shard1: 580） | 580 | 15〜20ラン |
| 永続強化ツリー完走 | 3,780 | 40〜60ラン（約20〜30時間）＝MVPの長期目標 |

- 検証基準: **「1ランで必ず何かが前進する」**（最低でも実績進捗かシャード10以上）を維持しつつ、全解放まで20時間以上を確保
- 供給側パラメータ（素点・ボーナス）は master の reward_tables 側に置き、コード変更なしで再調整可能にする

## 実装時の注意点
- キャラ・実績・永続強化ノードの code（`swordsman_rain`, `ach_runs_10`, `upg_hp_1` 等）はマスタseedスクリプトと本書を完全一致させる。名称変更はマスタのみで行いcodeは不変とする
- 成長率係数・初期値は characters テーブルの growth JSONB（CORE_SPEC §8 統合判断）に格納。計算はすべて `src/domain/progression/`（gainExperience, levelUp）で行いUI側で再計算しない
- シャード付与・実績解除・ランク計算は**リザルト確定API（API-307）内の単一トランザクション**で行い、currency_transactions への記録と冪等性（Idempotency-Key + ERR_REWARD_ALREADY_CLAIMED）を必ず両立させる
- 永続強化の効果適用は「ラン開始時（API-303）に初期値へ焼き込み run_state に保存」する方式とし、ラン中に player_upgrades を再参照しない（ラン中に購入しても現ランへ影響させない）
- レベルアップ成長の端数処理（floor + 最低+1保証）はdomain層でテスト（TC化）すること。特にspd+2%×係数0.9は低Lv帯で+0になりやすい
- 実績条件の判定箇所を分散させない: 「累計系」はplayer_progress統計の更新時、「ラン内系」はrun_state確定時に、AchievementModuleへ集約する
