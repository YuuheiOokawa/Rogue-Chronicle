# 08. UI/UX設計書 — Rogue Chronicle

## 目的

本書はローグライトRPG「Rogue Chronicle」（スマートフォン縦画面ファースト・ブラウザゲーム）のUI/UX設計を定義する。
設計原則・操作設計・戦闘UI・フィードバック演出・チュートリアル・デザインテーマ・デザイントークン・アクセシビリティを、実装可能な具体値で規定する。
画面ID（SCR-NNN）・API ID（API-NNN）・用語はCORE_SPEC（設計共通仕様）と完全一致させる。

## 1. 設計原則

### 1.1 スマートフォンファースト

- 基準ビューポート: **390×844px（iPhone 12〜15系）**。下限 **320×568px（iPhone SE 1st）** まで崩れないこと。
- レイアウトはモバイルを基準に作成し、PCはモバイルレイアウトを中央寄せで表示する（デスクトップ専用レイアウトは作らない）。
- ホバー前提のUIを作らない。ホバーで出す情報は必ず「タップ」または「長押し」でも到達できること。
- viewport meta: `width=device-width, initial-scale=1, viewport-fit=cover`。iOSのセーフエリアは `env(safe-area-inset-*)` でパディング確保（下部操作バーは `padding-bottom: max(12px, env(safe-area-inset-bottom))`）。

### 1.2 片手操作（親指リーチ）

主要操作（毎ターン・毎ノードで押すボタン）は**画面下1/3**に配置する。

```
┌─────────────────────┐  ← 0%
│  情報表示ゾーン（Hard）      │     敵・行動順・intent・お知らせ等
│  タップ必須要素を置かない     │     表示専用。タップは補助的（長押し詳細）
├─────────────────────┤  ← 33%
│  コンテンツゾーン（Stretch）  │     リスト・マップ・カード
│  スクロール可・選択操作可      │     届くが持ち替えが必要な範囲
├─────────────────────┤  ← 66%
│  操作ゾーン（Natural）       │     ★主要ボタンは必ずここ
│  攻撃/スキル/決定/出撃/購入   │     右手親指の自然可動域
│  ［キャンセルは左・決定は右］   │
└─────────────────────┘  ← 100%（セーフエリア考慮）
```

- 戦闘のコマンド（攻撃/スキル/防御/アイテム/逃走）、マップの「このノードへ進む」、各画面の決定ボタンは操作ゾーンに固定配置。
- 決定系ボタンは右側、キャンセル系は左側に統一（右手親指最優先。左手ユーザー向けの入れ替え設定は将来検討 → 未決事項 ISSUE-801）。
- ヘッダー（画面上部）に置いてよい操作は「戻る」「一時停止」「ヘルプ」の3種のみ。いずれも誤タップしても破壊的でないもの。

### 1.3 縦画面中心

- 全画面を**縦画面（portrait）専用レイアウト**として設計する。横画面レイアウトは作らない。
- 横画面（landscape）検出時: `matchMedia('(orientation: landscape)')` かつ画面高さ < 500px の場合、半透明オーバーレイ（背景 #0F1117 / 90%）に「縦画面でのプレイを推奨します」＋回転アイコンを表示する。**ゲームは停止しない**（オーバーレイ越しに閉じるボタンでプレイ続行可能。ブラウザゲームのため強制ブロックはしない。仮決定 DEC-081）。
- PCの横長ウィンドウはこの対象外（1.4のmax-width中央寄せで対応）。

### 1.4 PC表示（中央寄せ）

- ラン中・戦闘・結果系画面（SCR-301〜314, 401〜407）: **中央寄せ max-width 480px**。左右余白はダークファンタジー背景（グラデーション+ノイズ、7.7参照）で埋める。
- ホーム系・準備系・認証系・共通画面（SCR-001〜010, 101〜118, 201〜207）: **中央寄せ max-width 768px**（一覧系はグリッド2〜3列に拡張可）。（仮決定 DEC-082）
- 実装: レイアウトコンポーネント `GameShell`（480px）と `HomeShell`（768px）の2種を `src/components/layout/` に用意し、全ページはどちらかを必ず使う。

### 1.5 タップ領域

- すべてのインタラクティブ要素は**最小44×44px**（WCAG 2.5.5 / iOS HIG準拠）。
- 見た目が小さいアイコン（24pxアイコン等）は透明パディングでヒットエリアを44pxまで拡張する（`p-2.5` + `-m-2.5` パターン、または `min-w-11 min-h-11`）。
- 隣接するタップ要素の間隔は最小8px。戦闘コマンドボタン間は12px。
- リスト行の高さは最小56px（図鑑・一覧系）。

### 1.6 戦闘中の情報密度ルール

- **1画面に常時表示する主要情報は5つまで**とする。戦闘画面（SCR-302）の常時表示5要素:
  1. 行動順列（画面上部）
  2. 敵（姿・HPバー・intent・状態異常アイコン）
  3. プレイヤーHP/SPバー（数値併記）
  4. プレイヤーの状態異常・バフアイコン列
  5. コマンドボタン群（下1/3）
- 上記以外（スキルの詳細説明、バフの効果量、敵の詳細ステータス、レリック効果、戦闘ログ全文）は**長押し（2.4参照）またはステータス確認画面（SCR-311）へ退避**し、常時表示しない。
- テキストは戦闘中1要素につき最大2行。3行以上必要な情報は詳細ツールチップ側に置く。

## 2. 操作設計

### 2.1 重要操作の確認ダイアログ一覧

| 操作 | 画面 | ダイアログ種別 | タイトル文言 | 本文要点 | 確定ボタン | 補足 |
|---|---|---|---|---|---|---|
| 出撃 | SCR-207 出撃確認画面 | 画面自体が確認ステップ | 「この編成で出撃しますか？」 | キャラ・装備・永続強化適用値のサマリ表示 | 「出撃する」(primary) | ダイアログは重ねない（画面=確認） |
| リタイア | SCR-314 リタイア確認画面 | 2段階（2.3参照） | 「本当にリタイアしますか？」 | 「敗北扱いになります。ソウルシャードは80%持ち帰れます（現在: N個 → M個）」 | 「リタイアする」(danger) | 数値を必ず具体表示 |
| スキル削除 | SCR-307 休憩画面 / SCR-308 イベント画面 | モーダル | 「『{スキル名}』を削除しますか？」 | 「削除したスキルはこのラン中は戻せません」 | 「削除する」(danger) | 対象スキルのアイコン+効果を再掲 |
| 購入 | SCR-306 ショップ画面(ダンジョン内) | モーダル | 「『{商品名}』を購入しますか？」 | 「価格: {N} G（所持: {M} G → 残り {M-N} G）」 | 「購入する」(primary) | 残額を必ず表示。不足時はボタン自体をdisabled+「ゴールドが足りません」 |
| 退会 | SCR-116 設定画面 | 2段階モーダル+タイプ確認 | 「アカウントを削除しますか？」 | 「全データ（進行状況・キャラ・実績）が完全に削除され、復元できません」 | 「削除する」(danger) | 2段階目で「削除」と入力させる（タイプ確認）。API-008 |
| ログアウト | SCR-116 設定画面 | モーダル | 「ログアウトしますか？」 | ゲスト時のみ追加警告:「ゲストアカウントは再ログインできません。データ引き継ぎ（メール登録）を先に行ってください」 | 「ログアウトする」(danger) | ゲスト時は「引き継ぎ設定へ」(primary) を第一ボタンにする。API-003 |

ダイアログ共通ルール:
- 確定ボタンは右、キャンセルは左。破壊的操作の確定はdangerスタイル（7.6参照）。
- デフォルトフォーカス（Enterキー/最初のフォーカス）は常に**キャンセル側**。
- 背景タップ・Escキーで閉じる=キャンセル扱い（退会の2段階目のみ背景タップで閉じない）。

### 2.2 二重送信防止

- **クライアント側**: 送信ボタンは押下と同時に `disabled` + ラベル左にスピナー（16px、7.8のspin）表示。TanStack Query の `isPending` をボタンに直結。処理完了 or エラーまで再押下不可。連続タップ対策として押下後300msはpointer-events無効。
- **サーバー側**: ラン系変更API（API-303, 305, 306, 307, 402, 502〜508）は `Idempotency-Key` ヘッダ必須（CORE_SPEC 7章準拠）。キーはクライアントで `crypto.randomUUID()` を「操作の意図」単位で生成し、リトライ時は同一キーを再送する。重複時はサーバーが `ERR_DUPLICATE_REQUEST`(409) または初回結果のリプレイを返す。
- **楽観ロック**: run_state.version（DEC-011）をリクエストに含め、`ERR_CONFLICT_VERSION`(409) 時は API-304（現在ラン取得）で最新状態を再取得して画面を同期し、トースト「最新の状態に更新しました」を表示する。

### 2.3 誤操作防止

- **破壊的操作は2段階**: リタイア・スキル削除・退会・（ゲストの）ログアウトは「①操作起点タップ → ②確認ダイアログで確定」の最低2タップ。退会のみ3段階（＋タイプ確認）。
- **確認ダイアログの確定ボタンは表示後500ms間disabled**（連打の勢いで確定してしまう事故防止。リタイア・退会・スキル削除に適用）。
- **ボス戦前警告**: SCR-301 ダンジョンマップ画面でBOSSノード（階層10）を選択した際、ノード決定前にモーダル「この先はボス戦です。挑む前に休憩やステータスの確認を済ませましょう（この先は引き返せません）」＋「HP: {n}/{max}」を表示し、「挑戦する」(primary)/「マップに戻る」(secondary) の2択とする。ELITEノードは警告なし（ノードアイコンとラベルで判別可能とする）。
- 破壊的でない高頻度操作（攻撃・ノード移動・カード選択）には確認を挟まない（テンポ優先）。

### 2.4 長押しによる詳細表示（詳細ツールチップ）

| 対象 | 場所 | 表示内容 |
|---|---|---|
| スキル | 戦闘コマンド（SCR-302）/ スキル3択（SCR-303）/ 所持品確認（SCR-312）/ スキル図鑑（SCR-108） | 名称・レア度・SPコスト・倍率/効果値・属性・強化Lv（現在値と次Lv値）・付与する状態異常 |
| レリック | レリック取得（SCR-310）/ 所持品確認（SCR-312）/ レリック図鑑（SCR-109） | 名称・レア度・trigger種別・効果全文・呪い効果（あれば赤字） |
| 敵バフ/デバフ/状態異常 | 戦闘画面（SCR-302）の敵/プレイヤーのアイコン列 | 名称・効果（数値込み。例:「毒: ターン終了時 最大HPの8%ダメージ」）・残りターン数 |
| 敵の行動予告（intent） | 敵頭上のintentアイコン | 行動名・種別（攻撃/強撃/バフ/デバフ/回復/召喚）・予測数値（例:「強撃: 約24ダメージ」） |
| 装備 | 装備選択（SCR-309）/ 武器一覧（SCR-107） | 名称・レア度・slot・ステータス補正値 |

仕様:
- 発火: **長押し500ms**（`onPointerDown` から500msタイマー、移動10px超 or `pointerup` でキャンセル）。PCではホバー700msでも同一ツールチップを表示。
- 表示: 対象要素の上（画面上端に近い場合は下）に最大幅320pxのポップオーバー（surface色 #1A1D27、枠線 #2A2F3E、角丸8px、shadow-lg）。指を離すと閉じる（PCホバーはマウスアウトで閉じる）。
- 長押し中はOSのコンテキストメニュー・テキスト選択を抑止（対象要素に `select-none` と `-webkit-touch-callout: none`）。
- 長押し可能な要素には右上に小さな「ⓘ」ドット（6px、#9CA3AF）を付け、発見可能性を担保する。初回はコーチマークで案内（5.3参照）。

### 2.5 戻るボタンの挙動表

「戻る」は (a) 画面内の戻るボタン（ヘッダー左の「←」）、(b) ブラウザバック、(c) Androidの戻るジェスチャ（=ブラウザバック）の3系統。挙動を画面グループごとに定義する。

| 画面グループ | 対象SCR | 画面内「←」 | ブラウザバック | 方針 |
|---|---|---|---|---|
| 認証・共通 | SCR-002〜008 | 前画面へ（履歴通り） | 許容（そのまま） | 通常のWebページとして振る舞う |
| ホーム系 | SCR-101〜118 | ホーム（SCR-101）または一覧親画面へ | **許容**（履歴通り） | データ消失リスクなし。素直にhistoryに従う |
| 準備系 | SCR-201〜207 | 準備フローの1つ前のステップへ | 許容（ステップを1つ戻る） | 選択内容はZustandに保持し、戻っても選択が消えないこと |
| ラン中（マップ・ノード） | SCR-301, 305〜312 | SCR-301はヘッダー「≡」で一時停止画面（SCR-313）を開く。305〜312は完了前ならSCR-301へ | **一時停止画面（SCR-313）を開く**（離脱させない） | pushState介入（2.6）。報酬未受領（pendingReward）中はノードから戻れない |
| ラン中（戦闘） | SCR-302〜304 | 「←」なし（ヘッダーは一時停止「≡」のみ） | **一時停止画面（SCR-313）を開く** | 戦闘から任意画面へ戻る手段は置かない。逃走はコマンドとして提供 |
| 一時停止・リタイア | SCR-313, 314 | 直前のラン中画面へ復帰 | 直前のラン中画面へ復帰（モーダルを閉じる扱い） | |
| 結果系 | SCR-401〜407 | なし（進む導線のみ:「ホームへ」） | **無効化**（pushStateで同一画面に留め、トースト「リザルトを確定してください」） | API-307 finalize完了後はホームへ自動遷移するため戻る必要がない |

### 2.6 ブラウザバック対策

- ラン中画面（SCR-301〜314）と結果系（SCR-401〜407）では、画面表示時に `history.pushState` でダミーエントリを1つ積み、`popstate` イベントで (1) ラン中→SCR-313 一時停止画面を開く、(2) 結果系→留まる+トースト、の介入を行う。介入後は再度pushStateして防壁を維持する。
- `beforeunload` はラン中のみ登録し、タブ閉じ/リロード時にブラウザ標準の確認を出す（カスタム文言は不可のため標準文言）。
- **ただしデータ消失は起きない前提**: ラン状態は全てサーバー保存（DEC-011、run_state JSONB）であり、離脱してもAPI-304（現在ラン取得）で完全に再開できる。したがって上記介入は「データ保護」ではなく「意図しない離脱によるテンポ喪失の防止」が目的である。過剰にユーザーを引き留めない（beforeunloadの確認は1回のみ、ホーム系では一切登録しない）。
- 再訪時: SCR-101 ホーム画面表示時にAPI-304を照会し、activeなランがあれば「冒険を再開する」バナー（画面上部、accent金の枠）を最優先表示する。

## 3. 戦闘UI（SCR-302）

### 3.1 レイアウト（縦390px基準）

```
┌──────────────────────┐
│ [≡]  第3階層  ターン4   [?] │ ← ヘッダー 48px（一時停止/ヘルプ）
│ 行動順: ▶🗡️ 🦇 👤 💀      │ ← 行動順列 44px
├──────────────────────┤
│      敵エリア（〜45%）       │
│   [intent]  [intent]        │ ← 敵頭上に行動予告
│    敵A       敵B            │ ← 敵1〜3体。タップでターゲット選択
│   ▓▓▓░ HP   ▓▓░░ HP        │ ← 敵HPバー+数値
│   ☠2 🔻1                   │ ← 状態異常/デバフ（残ターンバッジ）
├──────────────────────┤
│ ダメージログ帯（直近1行）     │ ← 32px 「レインの攻撃！ 18ダメージ」
├──────────────────────┤
│ レイン Lv5  ▲1 ☠2          │ ← プレイヤーバフ/状態異常列
│ HP ▓▓▓▓▓▓▓░░ 74/100        │ ← HPバー 12px+数値
│ SP ▓▓▓▓▓░░░░░  5/10        │ ← SPバー 8px+数値
├──────────────────────┤
│ ［攻撃］［スキル］            │ ← 操作ゾーン（下1/3）
│ ［防御］［アイテム］［逃走］    │    ボタン高48px
└──────────────────────┘
```

### 3.2 ダメージ表示（フローティング数字）

| 種別 | 表示 | フォント/サイズ | 色 | アニメーション |
|---|---|---|---|---|
| 通常ダメージ | 「18」 | 等幅太字 24px | #F3F4F6（白） | 対象の頭上から上方向へ32pxフロート+フェードアウト、600ms、ease-out |
| クリティカル | 「36!」 | 等幅太字 **34px** | **#F59E0B（橙金）**+text-shadow発光 | フロート800ms+**スケール1.3→1.0**+対象スプライトを左右±4pxシェイク150ms |
| 属性有利 | 数字の左に属性アイコン | 同上 | 数字色は通常/クリに準拠 | 「弱点!」ラベル（12px）を数字下に併記 |
| 回避 | 「MISS」 | 等幅 20px | #9CA3AF（灰） | 横スライド+フェード400ms |
| 回復 | 「+12」 | 等幅太字 24px | #22C55E（HP緑） | 上方向フロート600ms |
| 状態異常ダメージ（毒/火傷） | 「-8」+状態アイコン | 等幅 20px | 毒 #A3E635 / 火傷 #F97316 | ターン終了時にまとめて順次表示（1件120ms間隔のstagger） |

- 複数ヒットは120ms間隔で順次出現。同時最大表示は8個（超過分は即時合算表示に切替、パフォーマンス維持）。
- 実装はFramer Motionの `AnimatePresence` + `transform/opacity` のみ使用（reflowを起こすtop/left直接アニメ禁止）。

### 3.3 状態異常表示

- 対象（敵/プレイヤー）の名前行の下に**アイコン列**として表示。アイコン20px、右下に**残りターン数バッジ**（10px円形、背景 #0F1117/80%、白数字、例: ☠の右下に「2」）。
- MVP5種のアイコン割当（lucide-react / 代替絵文字）: 毒=Skull/☠（緑 #A3E635）、火傷=Flame/🔥（橙 #F97316）、麻痺=Zap/⚡（黄 #FACC15）、スタン=Star/💫（黄 #FDE047）、弱体=ShieldMinus/🛡（紫灰 #A78BFA）。
- 5個を超えた場合は先頭4個+「+N」チップ。タップで全件リスト（ポップオーバー）。
- 付与された瞬間は対象頭上に「毒を付与!」テキスト（14px、状態色）を800msフロート表示。

### 3.4 行動順表示

- **画面上部（ヘッダー直下）にSPD降順のアイコン列**を横並び表示（CORE_SPEC 5.1: spd降順、同値はプレイヤー優先）。
- 各アイコンは32px円形（プレイヤー=キャラ顔、敵=敵ミニアイコン）。現在行動中のユニットは左端+accent金（#D4AF37）のリング2px+左に「▶」マーカー。
- 行動済みは不透明度40%。ターンをまたぐ位置に細い区切り線（#2A2F3E）を入れ、「次ターンの順番」まで最大8枠先読み表示。
- アイコンタップで対象ユニットの簡易ステータス（名前・HP・SPD）をポップオーバー表示。

### 3.5 敵の行動予告（intent）

- **全敵の頭上にintentアイコン+数値**を常時表示（CORE_SPEC 5.7: 行動予告を全敵に表示）。
- サイズ: アイコン24px+数値14px等幅。敵スプライトの上8pxに配置。
- 種別と表示:

| intent種別 | アイコン（lucide / 絵文字） | 数値表示 |
|---|---|---|
| 攻撃 | Sword / 🗡️ | 予測ダメージ「12」 |
| 強撃 | Swords+赤縁 / ⚔️ | 予測ダメージ「24」+アイコン点滅（1.2s周期、opacity 1→0.6） |
| 全体攻撃 | Sword+「ALL」ラベル / 🗡️ALL | 予測ダメージ |
| バフ | TrendingUp+▲ / ▲ | なし（長押しで詳細） |
| デバフ | TrendingDown+▼ / ▼ | なし |
| 回復 | Heart / 💚 | 予測回復量 |
| 召喚 | UserPlus / ✨ | なし |
| 不明（ボス特殊時のみ） | HelpCircle / ？ | なし |

- 予測ダメージはサーバーが計算した期待値（乱数0.90〜1.10・クリ除外の中央値）をAPI-401/402応答に含め、クライアントは表示のみ行う（DEC-007サーバー権威）。
- ボス「遺跡の守護者」のフェーズ移行時は全体攻撃予告を**画面上部の帯（幅100%、#EF4444/15%背景、「守護者が大技を構えている…!」）**でも二重に警告する。

### 3.6 HP/SP/バフ・デバフの視認性

- **バー+数値を必ず併記**（バーだけ/数値だけを禁止）。プレイヤーHPバー高さ12px・SPバー8px、敵HPバー8px。数値は等幅フォント14px「74/100」形式。
- HPバー色は残量で段階変化: 51%以上 #22C55E → 21〜50% #FACC15 → 20%以下 #EF4444+バー点滅（1s周期）。**色変化と同時にバー内テクスチャも変化**（低HP時は斜線パターン）させ、色覚に依存しない。
- SPバーは常に #3B82F6。スキルボタンにはSPコストを常時表示し、SP不足のスキルはdisabled+コスト数字を赤 #EF4444。
- ダメージ時はバーの減少分を白いゴースト（減少前の値の残像）として300ms遅れて追従させ、削れた量を視認可能にする。

### 3.7 色だけに依存しない設計

- **バフ=上向き三角「▲」/ デバフ=下向き三角「▼」**をアイコンに必ず併用する（例: atkUp=🗡️▲、defDown=🛡️▼）。色（バフ緑/デバフ赤）は補助情報とする。
- 状態異常はすべて形状の異なるアイコン+長押しでテキスト名称を確認可能（3.3・2.4）。
- 属性は色+シンボルで表現: 火=🔥赤 #EF4444、水=💧青 #3B82F6、風=🌪緑 #34D399、無=◇灰 #9CA3AF。属性相性の有利/不利はダメージ数字への「弱点!」「耐性」テキスト併記で伝える。
- レア度も色+形状: common=灰枠、rare=青枠+左上ダイヤ1個、epic=紫枠+左上ダイヤ2個+微発光。

## 4. フィードバック

### 4.1 報酬獲得演出（カードめくり）

- 宝箱（SCR-305）・戦闘報酬・スキル3択（SCR-303）・レリック取得（SCR-310）は**カードめくり**で統一する。
- 裏面（紋章+ノイズテクスチャ）→ `rotateY 180deg` フリップ400ms（ease-out）で表面公開。複数枚は左から順に**stagger 150ms間隔**。
- フリップ完了までタップ不可（誤選択防止）。ただし画面タップで**演出スキップ**（全カード即公開）可能。演出は常にスキップ可能とする（周回ゲームのテンポ優先）。
- カードサイズ: 3択時 幅30%（約104px）×高さ160px、単独報酬時 幅60%×高さ240px。

### 4.2 レア報酬特別演出

| レア度 | 演出 |
|---|---|
| common | フリップのみ |
| rare | フリップ+青（#3B82F6）の縁発光（box-shadow 0 0 16px） |
| epic | フリップ前にカード裏面が**紫（#8B5CF6）に発光**（box-shadow 0 0 24px、脈動1.2s×2回）→ フリップと同時に**画面フラッシュ**（白 #FFFFFF opacity 0.35 → 0、250ms）+ 紫パーティクル風の放射線（CSSのconic-gradient回転、600ms） |

- 画面フラッシュは `prefers-reduced-motion` 時および設定「演出を軽くする」ON時には**発光のみに減格**する（光過敏への配慮、8章）。

### 4.3 レベルアップ演出（SCR-304 → SCR-303 連続表示）

1. 戦闘勝利処理後、「LEVEL UP!」バナー（画面中央、Shippori Mincho 32px、accent金 #D4AF37、下からスライドイン300ms）。
2. 上昇ステータスを1行ずつstagger 100msで表示（「HP 100 → 108」「ATK 12 → 13」等、等幅フォント。全回復はしない仕様のためHP現在値は割合維持で表示）。
3. 「スキルを選ぶ」ボタン → SCR-303 スキル選択画面（3択カードめくり、4.1）へ連続遷移。リロールボタン（残回数バッジ付き）とスキップボタンを下部に配置。
4. 複数レベルアップ時は1レベルずつ繰り返し（3択も回数分）。演出部分はタップでスキップ可。

### 4.4 ローディング

- **500msルール**: 応答が500ms未満で返る想定の操作にはローディングUIを出さない（チラつき防止）。500ms経過時点でスピナー表示（遅延表示は `useDeferredLoading(500)` フックで共通化）。
- **一覧・図鑑・ホームはスケルトン表示**（surface色 #1A1D27の角丸ブロック+shimmer 1.5s）。スケルトンは実レイアウトと同じ寸法（リスト行56px×表示予定件数、最大8行）。
- 画面全体のブロッキングローディング（全画面スピナー）は初回起動（SCR-001 スプラッシュ）とAPI-303 出撃直後のみ許可。それ以外は部分ローディングとする。
- 戦闘中の行動送信（API-402）は、コマンドボタンをdisabled+スピナーにするだけで画面は覆わない（p95 800ms以内想定）。

### 4.5 トースト通知

- 位置: **画面上部**（ヘッダー下8px、中央寄せ、幅=画面幅-32px、最大360px）。表示時間**3秒**、スワイプ上方向で即時消去可。同時表示は最大2件（3件目以降はキュー）。
- 用途: 実績解除（SCR-407。「実績解除: 累計ラン10回」+トロフィーアイコン+accent金枠）、保存完了（「保存しました」）、設定反映、楽観ロック再同期、軽微エラー（4.7）。
- 構成: アイコン24px+テキスト14px（最大2行）+（任意）アクションリンク1個。背景 #1A1D27/95%、角丸8px、shadow-lg。
- `role="status"`（実績・保存）/ `role="alert"`（エラー）を付与（8章）。

### 4.6 モーダル設計ルール

- 種類は2つのみ: **センターモーダル**（確認ダイアログ・退会等。幅=画面幅-48px、max-width 400px）と**ボトムシート**（詳細表示・フィルタ等の情報量が多いもの。下から380ms slide-up、上部にグラバー、最大高80vh、内部スクロール可）。
- 重ね表示は最大2枚まで（例: 設定画面ボトムシート+退会確認モーダル）。3枚目が必要な設計は画面遷移に変更する。
- オーバーレイ: #0F1117 / opacity 0.7。開閉アニメ: fade+scale(0.96→1) 200ms。
- フォーカストラップ必須・開時に `body` スクロールロック・閉じたら起点要素へフォーカス返却（8章）。
- モーダル内に主要ボタンは最大2個（primary/secondary or danger/ghost）。3択以上はボトムシートのリスト形式にする。

### 4.7 エラー表示

| 深刻度 | 表示 | 対象例 |
|---|---|---|
| 軽微（自動回復可・再操作で解決） | **トースト**（赤系: 左端に4pxの#EF4444バー+AlertCircleアイコン） | ERR_VALIDATION、ERR_INSUFFICIENT_GOLD/SHARDS、ERR_RATE_LIMITED（「しばらく待ってから再度お試しください」）、ERR_CONFLICT_VERSION（再同期して通知） |
| 致命（操作継続不能） | **モーダル+リトライボタン** タイトル「通信に失敗しました」+本文（traceId表示を含む）+「再試行」(primary)/「ホームへ戻る」(ghost) | ERR_TIMEOUT、ERR_INTERNAL、ネットワーク切断、ERR_RUN_STATE_INVALID（「最新の状態を読み込み直します」+API-304再取得） |
| 全体停止 | 専用画面へ遷移 | ERR_MAINTENANCE → SCR-009 メンテナンス画面 / 継続的な通信不能 → SCR-010 通信エラー画面（「再読み込み」ボタン付き） |
| 認証切れ | モーダル「セッションの有効期限が切れました」→ SCR-003 ログイン画面へ | ERR_AUTH_SESSION_EXPIRED、ERR_AUTH_UNAUTHORIZED |

- リトライは同一 `Idempotency-Key` で再送する（2.2）。「再試行」は最大3回、以降はSCR-010へ誘導。
- エラー文言は「原因+次の行動」を1〜2文で。エラーコードとtraceIdはモーダル下部に10px灰色で表示（問い合わせ用）。

## 5. チュートリアル・初心者誘導

### 5.1 初回ラン強制チュートリアル

- 初回の出撃は**短縮5階層の専用チュートリアルラン**（forgotten_ruinsの短縮構成: 階層1=開始戦闘、2=マップ分岐説明（BATTLE/TREASURE）、3=休憩（REST）、4=強敵（STRONG、intentの読み方）、5=ミニボス）を強制する（仮決定 DEC-083。スキップ不可、ただし2回目以降のアカウントデータ削除→再作成時の再表示はチュートリアルフラグで抑止）。
- 誘導方式: **ステップ吹き出し（コーチマーク）**。対象UIだけをくり抜いたスポットライト（オーバーレイ #0F1117/80%、対象部はcutout+accent金の枠）+吹き出し（最大2文・60字以内）+「次へ」ボタン。対象が操作可能なステップでは「実際にタップさせて」進行する。
- 必須ステップ（計12ステップ以内）:
  1. 戦闘: 攻撃ボタン → 2. 敵のintentの見方 → 3. スキル使用とSPコスト → 4. HP/SPバーの見方 → 5. 勝利とEXP
  6. マップ: ノード選択（分岐の概念）→ 7. ノードタイプアイコンの意味
  8. レベルアップ: スキル3択の選び方（長押しで詳細、を必ず1回実行させる）
  9. 休憩: 回復かスキル強化かの二択
  10. 強敵: 強撃intentへの防御コマンド誘導
  11. ミニボス撃破 → 12. リザルト: ソウルシャードと永続強化（SCR-106）への導線案内
- チュートリアル完了フラグはサーバー保存（user_settings）。LocalStorageには進行中ステップ番号のみキャッシュ（DEC復帰用、CORE_SPEC 10章のLocalStorage方針準拠）。

### 5.2 ヘルプへの導線

- SCR-117 ヘルプ画面をハブとし、(1) ホームのメニュー内、(2) 戦闘画面ヘッダー右の「?」（44px）、(3) 一時停止画面（SCR-313）内「遊び方」、(4) 各Empty Stateの3経路以上から到達可能にする。
- 戦闘中の「?」は現在の文脈（戦闘の基本・状態異常一覧・属性相性表）を直接開く（コンテキストヘルプ）。ヘルプはボトムシートで表示し、戦闘状態は背後で保持される（ターン制のため時間経過なし）。

### 5.3 ツールチップ初回表示

- 初出のUI要素には**初回のみ**1件ずつコーチマークを表示する（同時に複数出さない。1画面1回まで）:
  - 初めてのレリック取得時:「レリックは長押しで効果を確認できます」
  - 初めて状態異常を受けた時:「アイコン長押しで効果と残りターンを確認できます」

## 6. デザインテーマ

### 6.1 3案比較

| 評価軸 | A. ダークファンタジー | B. 魔法図書館 | C. 王道ファンタジー |
|---|---|---|---|
| 世界観適合（忘却の遺跡・ソウルシャード・呪いレリック） | ◎ 遺跡探索・呪い・深淵と直結 | ○ 「年代記・図鑑」要素とは好相性だが、ダンジョン探索の緊張感と乖離 | ○ 汎用的に適合するが世界観の固有性が薄い |
| 実装コスト（CSSのみで成立するか） | ◎ 暗背景+発光アクセントはCSSグラデーション+box-shadowで表現でき、画像アセット最小で成立 | △ 本棚・紙・羊皮紙テクスチャ等、画像アセット依存が高い | △ 明色背景は情報の視認性確保が難しく、装飾画像が必要になりがち |
| 差別化（他ブラウザゲーとの差） | ○ 定番だが完成度で差別化可能。ローグライト層（Slay the Spire等）の期待と一致 | ◎ 独自性は最も高い | △ 最も没個性になりやすい |
| アセット調達性（フリー素材・アイコンの入手性） | ◎ ダーク系UI素材・lucideアイコンとの親和性が高い。絵文字代替も暗背景で映える | △ 図書館系素材は少ない | ○ 素材は多いが画風の統一が難しい |
| ダークモード端末との親和性・有機EL消費電力 | ◎ | △ | △ |
| 長時間プレイの目の負担 | ◎ 暗基調は夜間プレイに有利 | ○ | △ 明基調は眩しい |

### 6.2 選定: ダークファンタジー（DEC-015）

**ダークファンタジーを採用する（DEC-015）。** 理由:
1. 「忘却の遺跡」「ソウルシャード」「呪い付きレリック」というゲーム内概念と世界観が直結し、追加の説明コストなく没入できる。
2. 暗色背景+発光アクセントはCSS Animation+Framer Motionのみ（DEC-009）で「豪華に見える」表現が最も安く作れる。epicの紫発光・ダメージ数字・金アクセントはすべて暗背景あってこそ映える。
3. 個人開発のアセット制約（画像最小方針、7.7）と最も相性が良い。
4. 主要ターゲット（ローグライト経験者）の期待するトーンと一致する。

なお「魔法図書館」要素は捨てず、図鑑（SCR-108〜110）・実績・リザルトの「記録される」演出モチーフ（羊皮紙風カード・インク文字）としてサブテーマ的に取り込む（仮決定 DEC-084）。

| 数値（ダメージ・HP/SP・ゴールド・タイマー） | 等幅: Roboto Mono（数字のみ使用のためサブセット軽量） | 14〜34px/700。`font-variant-numeric: tabular-nums` |

- 配信: `next/font/google` でセルフホスト相当の最適化（`display: swap`）。Shippori Minchoは見出し用サブセット（weight 700のみ）に限定し、初期ロードを抑える。
- 最小フォントサイズ14px（8章）。ボタンラベル16px。バッジ等の例外は10px以上かつ長押し詳細で補完される情報に限る。

### 7.3 アイコン

- 基本: **lucide-react**（stroke 2px、サイズ20/24px）。UI操作系（戻る・設定・閉じる・ヘルプ等）はすべてlucideで統一。
- ゲーム内シンボル（属性・状態異常・ノードタイプ・intent）: MVPは**絵文字を第一実装**（🔥💧🌪☠⚡等。プラットフォーム差異は許容）とし、コンポーネント `GameIcon` に集約して将来SVG差し替え可能にする（仮決定 DEC-087）。lucideに適切なものがある場合（Sword, Skull, Flame等）はlucide優先。
- アイコン単独で意味を伝えない: 必ずラベル併記または長押し詳細（2.4）とセットで使う。装飾アイコンは `aria-hidden="true"`。

### 7.5 カード

- 汎用カード: 背景 surface #1A1D27、角丸12px、枠線1px #2A2F3E、内側パディング16px、`shadow-md`（0 4px 12px rgba(0,0,0,0.4)）。
- 報酬/スキル/レリックカード: 上記+レア度枠線（common: #9CA3AF 1px / rare: #3B82F6 1.5px / epic: #8B5CF6 2px+`shadow-[0_0_16px_rgba(139,92,246,0.35)]`）。構成は「上: アイコン48px → 中: 名称14px/700 → 下: 効果概要12px（2行まで、以降は長押し）」。
- 選択状態: 枠線をaccent金 #D4AF37 2px+チェックマーク右上表示（色だけに依存しない）。

### 7.6 背景

- 基本背景: `linear-gradient(180deg, #0F1117 0%, #141726 55%, #0F1117 100%)` +**ノイズテクスチャ**（SVG `feTurbulence` をdata URI化した128pxタイル、opacity 0.04、`background-blend-mode: overlay`）。画像アセットを使わずCSS+インラインSVGのみで質感を出す。
- 場面別の差し色（グラデーション中間色のみ変更）: ホーム=#141726（紺紫）/ ダンジョン=#161320（暗紫）/ 戦闘=#1A1420（赤みの暗紫）/ ボス戦=#201218（暗赤）/ リザルト=#171B15（暗金緑）。
- 画像アセットは「キャラ立ち絵・敵スプライト・ボス背景1枚」の最小限に限定（仮決定 DEC-088）。装飾は全てCSS表現とする。

### 7.7 エフェクト方針（DEC-009: CSS Animation + Framer Motion のみ）

使用箇所一覧:

| 箇所 | 実装 | 時間/仕様 |
|---|---|---|
| 画面遷移フェード | Framer Motion `AnimatePresence`（opacity 0→1） | **150ms** ease-out。ラン中のノード間遷移も同一 |
| ダメージ数字フロート | Framer Motion（y: 0→-32, opacity 1→0） | 600ms（クリ800ms）。3.2参照 |
| カード出現stagger | Framer Motion `staggerChildren: 0.15` | フリップ400ms+間隔150ms。4.1参照 |
| ボス登場 | 画面暗転（opacity 0.9、400ms）→ ボス名タイトル（Shippori Mincho 28px、letter-spacing 0.3em、フェード+拡大 800ms）→ 暗転解除 | 合計1.6s、タップスキップ可 |
| HPバー増減 | CSS `transition: width 300ms ease-out` +ゴースト残像（3.6） | 300ms |
| トースト | Framer Motion（y: -16→0） | 入り200ms/出150ms |
| モーダル/ボトムシート | fade+scale 200ms / slide-up 380ms | 4.6参照 |
| ボタン押下 | CSS `active:scale-[0.98]` | 100ms |
| スケルトンshimmer | CSS `@keyframes`（背景位置移動） | 1.5s無限 |
| epic発光・低HP点滅・強撃intent点滅 | CSS `@keyframes`（box-shadow / opacity） | 4.2・3.6・3.5参照 |

パフォーマンス規約:
- アニメーションは `transform` と `opacity` のみ（width遷移はHPバーのみ例外的に許可、要素が小さくreflow影響が限定的なため）。**60fps維持**を目標とし、`will-change` は同時適用3要素まで。
- 同時アニメーション要素は最大10個。超える場合は間引くか合算表示（3.2）。
- `prefers-reduced-motion: reduce` 時: 全アニメーションを「即時切替 or フェードのみ（100ms）」に減格するグローバルスイッチを `MotionConfig reducedMotion="user"` +CSSメディアクエリで実装。画面フラッシュ・シェイク・点滅は無効化。設定画面（SCR-116）にも「演出を軽くする」トグルを用意し、OS設定と独立して制御可能にする。
- Canvas/PixiJS等への切替条件（DEC-009の将来条件）: 同時パーティクル50個超の演出要求、または実測でミッドレンジ端末（4世代前のAndroid相当）が45fpsを下回った場合に再検討する。

## 8. アクセシビリティ

- **コントラスト比**: 本文テキストは背景に対し**4.5:1以上**（text #E5E7EB on bg #0F1117 ≒ 15.7:1、text-sub #9CA3AF on surface #1A1D27 ≒ 6.5:1 でクリア）。18px以上の見出し・disabled表示は3:1以上。CIでは主要組合せをテスト固定値として検証する。accent金 #D4AF37 on bg は約8.9:1で本文使用可、ただしボタン背景としては白文字とのコントラスト不足（約1.8:1）のため**金背景ボタンは作らない**（金は枠線・テキスト・アイコン用途に限定）。
- **フォーカスリング**: すべてのインタラクティブ要素に `focus-visible:outline outline-2 outline-offset-2 outline-primary`（#8B5CF6）。マウス/タップ時は非表示（`:focus-visible` のみ）。フォーカス順はDOM順=視覚順に一致させる。
- **スクリーンリーダー用aria方針**:
  - 完全対応（全戦闘ログ読み上げ等）はMVPスコープ外とし、**「ナビゲーションと状態把握が可能」レベル**を保証する（仮決定 DEC-089）。
  - HP/SPバー: `role="meter"` + `aria-valuenow/min/max` + `aria-label="HP 74/100"`。
  - ダメージ・回復・状態異常付与の要約は `aria-live="polite"` のログ領域（視覚的には3.1のダメージログ帯）へ1行ずつ出力。トーストは `role="status"` / エラーは `role="alert"`（4.5・4.7）。
  - モーダル: `role="dialog"` + `aria-modal="true"` + `aria-labelledby`。フォーカストラップと起点返却（4.6）。
  - アイコンのみのボタンは必ず `aria-label`（例: `aria-label="一時停止"`）。装飾アイコン・絵文字は `aria-hidden="true"` とし、意味はテキストで併記。
  - 長押しツールチップの内容は、スクリーンリーダー利用時は対象要素の `aria-describedby` で到達可能にする。
- **フォントサイズ**: 本文最小**14px**。ブラウザのテキスト拡大（ページズーム200%）でレイアウトが破綻しない（横スクロールを発生させない）こと。remベース指定を基本とする。
- **色非依存**: 3.7の通り（バフ▲/デバフ▼、HPバーのテクスチャ変化、レア度の形状差）。
- **タップ領域44px・操作の代替手段**: 1.5・2.4の通り。長押し情報はPCではホバー、SRではaria-describedbyで代替。

## 実装時の注意点

1. **サーバー権威との整合（DEC-007）**: ダメージ数字・intent予測値・報酬内容は全てAPI-401/402/503等の応答値をそのまま表示する。クライアントで計算式を再実装して表示しない（表示と実値のズレはチート報告と区別できない）。
2. **冪等キーの生成単位**: 「ボタン押下ごと」ではなく「操作の意図ごと」に `Idempotency-Key` を生成し、リトライ（4.7）では同一キーを再送すること。押下ごとに再生成すると二重実行防止にならない。
3. **アニメーションと状態更新の分離**: 演出スキップ（4.1・4.3）実装のため、ゲーム状態の更新（TanStack Queryキャッシュ反映）は演出完了を待たずに行い、演出は表示層のみで完結させる。演出中の再レンダリングでアニメが巻き戻らないよう、演出キューはZustandで管理する。
4. **history介入の実装順序**: pushState防壁（2.6）はレイアウト（`GameShell`）で一元実装する。画面ごとに個別実装するとエントリが多重に積まれ「戻るが効かないバグ」になりやすい。
5. **prefers-reduced-motionは初期実装から**: 後付けは全アニメ箇所の洗い出しが必要になる。`MotionConfig` とTailwindの `motion-reduce:` を最初から通すこと。
6. **フォントサブセット**: Roboto Monoは数字+記号のみ、Shippori Minchoは700のみに限定し、`next/font` の `subsets`/`weight` 指定で配信量を抑える（LCP 3秒目標）。
7. **44pxヒットエリアの検証**: Playwrightのビューポート390×844でタップ要素の `boundingBox` を検査するテストを共通化する（回帰防止）。
8. **絵文字アイコンの集約**: 絵文字を直接JSXに書かず、必ず `GameIcon` コンポーネント経由にする（将来のSVG差し替え・aria-hidden付与漏れ防止、DEC-087）。
9. **トーストとaria-liveの二重読み上げ防止**: トースト本体とダメージログ帯の両方に同一情報を流さない。戦闘系はログ帯、システム系はトーストと役割分担する。
10. **スケルトンの寸法固定**: スケルトン（4.4）と実データのレイアウト寸法を共通コンポーネントの定数から参照し、CLS（レイアウトシフト）を防ぐ。
