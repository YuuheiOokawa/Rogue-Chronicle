# 06. 画面一覧（Screen List）

- 対象プロダクト: Rogue Chronicle（ローグライトRPG / DEC-001（仮決定））
- 目的: 全画面の一覧・遷移関係・利用者・MVP対象・関連APIを単一の表で定義し、画面遷移設計（07）・ワイヤーフレーム（08）・API設計（13）の基準とする
- 関連文書: CORE_SPEC §6・§7、docs/07_Screen_Transition.md

## 1. 前提・凡例

- 画面IDと画面名は CORE_SPEC §6 と完全一致させる（全56画面を掲載。うちMVP対象は「○」50画面）。
- 区分: 共通 / 認証 / ホーム / 準備 / ラン中 / 結果
- 利用者:
  - 未認証: セッションを持たない状態でアクセス可能
  - ゲスト・一般: 認証済みであればゲストアカウント（users.is_guest=true）・一般アカウントの両方が利用可能
  - ゲストのみ: ゲストアカウント専用
- MVP対象: ○=MVPで実装 / △=MVPで他画面に統合（独立画面は作らない） / ×=将来
- 関連API: CORE_SPEC §7 のAPI-NNNと完全一致。「—」はAPI呼び出しなし（静的表示、またはクライアント保持データの参照のみ）

## 4. 画面間の依存関係サマリ

- 認証必須境界: SCR-101以降の全画面は認証必須（API-004で検証）。401検知時は一般アカウントはSCR-003へ、ゲストはトークン再発行を試行（07 §6参照）。
- ラン存在境界: SCR-301〜314・401〜403はアクティブランが存在する場合のみ表示可。存在しない状態でアクセスした場合はAPI-304が404/該当なしを返し、SCR-101へリダイレクトする。
- 準備フロー境界: SCR-204〜207は選択状態（ダンジョン/キャラ/装備）をクライアント状態（Zustand, DEC-008）で保持し、直アクセス時は選択が欠けていればSCR-202へ戻す。

## 実装時の注意点

- 画面ID・画面名・API IDはCORE_SPEC §6・§7と完全一致させること。新画面追加時はCORE_SPECを先に更新する。
- (run)グループの全ルートは`beforeunload`とhistory介入（popstate）の離脱ガードを共通レイアウトに実装し、個別画面で重複実装しない（07 §6参照）。
- ラン系変更API（API-303, 305, 306, 307, 402, 502〜508）は必ず `Idempotency-Key` ヘッダとrun_state.version（楽観ロック、DEC-011）を付与する。ボタンは応答受領まで無効化する。
- 統合画面（SCR-103/203/304/404）はコード上もコメントで元の画面IDを明記し、将来の分離を容易にする。
- モーダル実装画面（SCR-311〜314, 406）はフォーカストラップ・Escapeキー対応・スクリーンリーダー対応（role="dialog"）を共通モーダルコンポーネント（shadcn/ui Dialog、DEC-010）で実装する。
- ゲストと一般で利用可能画面は同一（SCR-006のみゲスト専用）。ゲストにはホーム・設定に「データ引き継ぎ」導線を常設する。
